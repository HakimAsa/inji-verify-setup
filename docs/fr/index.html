Remarque

Nécessite l'installation préalable de Docker. Cette étape peut être ignorée si Docker Desktop (Windows) est installé, car il inclut déjà Docker Compose. Installez Docker via les liens ci-dessus avant de poursuivre.

  • Installer en tant que plugin de la commande docker
  • Installer Docker Compose en version autonome

Une fois l'installation terminée, suivez la section Exécution pour lancer Inji Verify en local, à des fins de démonstration.

02 Configuration des portefeuilles Web

Le tableau WebWallets du fichier config/config.json définit le ou les portefeuilles web disponibles pour le flux VP sur un même appareil (Same Device).

config/config.json
"WebWallets": [
  {
    "id": "inji-wallet",
    "name": "Inji Wallet",
    "iconUrl": "/assets/inji-web-wallet-icon.svg",
    "walletBaseUrl": "https://injiweb.dev-int-inji.mosip.net"
  }
]
Dépendance externe

La valeur par défaut de walletBaseUrl pointe vers une instance de développement/intégration partagée d'Inji Web Wallet, hébergée par MOSIP. Les flux de portefeuille échoueront silencieusement si cet hôte est indisponible, retiré ou inaccessible depuis votre réseau.

Avant d'exécuter l'application en local, remplacez walletBaseUrl par l'une des valeurs suivantes :

ScénarioValeur de walletBaseUrl
Instance Inji Web Wallet déployée par vous-mêmehttps://<votre-hote-inji-web-wallet>
Inji Web Wallet en local (port par défaut)http://localhost:3001
Simuler / désactiver l'entréeSupprimer l'entrée du tableau
config/config.json
"WebWallets": [
  {
    "id": "inji-wallet",
    "name": "Inji Wallet",
    "iconUrl": "/assets/inji-web-wallet-icon.svg",
    "walletBaseUrl": "http://localhost:3001"
  }
]

Voir Inji Web Wallet pour les instructions d'installation d'une instance personnelle.

03 Configuration OpenID4VP

Le fichier de configuration se trouve dans le répertoire config.

Exemple commenté : « MOSIP ID »

Prenons l'exemple « MOSIP ID » pour comprendre comment ces propriétés fonctionnent ensemble :

config/config.json
{
  "logo": "/assets/cert.png",
  "name": "MOSIP ID",
  "type": "MOSIPVerifiableCredential",
  "essential": true,
  "clientIdScheme": "did",
  "definition": {
    "purpose": "Relying party is requesting your digital ID for the purpose of Self-Authentication",
    "format": {
      "ldp_vc": { "proof_type": ["RsaSignature2018"] }
    },
    "input_descriptors": [
      {
        "id": "id card credential",
        "format": {
          "ldp_vc": { "proof_type": ["RsaSignature2018"] }
        },
        "constraints": {
          "fields": [
            {
              "path": ["$.type"],
              "filter": {
                "type": "object",
                "pattern": "MOSIPVerifiableCredential"
              }
            }
          ]
        }
      }
    ]
  }
}
PropriétéRôle
logoImage affichée sur le panneau de sélection des identifiants (/assets/cert.png).
nameNom affiché sur le panneau de sélection des identifiants.
typeIdentifie en interne le type d'identifiant concerné.
essentialCet identifiant est requis pour que la vérification réussisse.
clientIdScheme: didLa requête VP utilise did comme client_id_scheme ; la requête d'authentification est accessible au portefeuille via request_uri.
clientIdScheme: pre_registeredLa requête VP utilise pre_registered ; la requête d'authentification est incluse directement dans la requête VP.
definitionLa définition de présentation pour ce type d'identifiant — voir DIF.PresentationExchange.

04 Proxy pour localhost

Pour faire fonctionner le flux OpenID4VP en local, utilisez un service de proxy comme ngrok ou localtunnel afin de créer une URL publique — par exemple https://proxyurl.ngrok.app — qui redirige vers http://localhost:3000.

C'est nécessaire car le portefeuille exécuté sur votre mobile ou tablette ne peut pas atteindre http://localhost:3000 au moment du partage des identifiants — cette adresse n'existe que sur votre propre machine.

Astuce

Ce proxy n'est utile que pour tester le partage d'identifiants avec un portefeuille mobile (flux multi-appareils ou même appareil ci-dessous). Si vous voulez simplement explorer l'interface dans votre navigateur, vous pouvez ignorer entièrement cette étape.

Étapes

  1. Démarrez votre proxy (ngrok, localtunnel…) vers le port 3000.
  2. Dans docker-compose.yml, remplacez chaque occurrence de VERIFY_SERVICE_PROXY_FOR_LOCALHOST par le nom d'hôte du proxy (par ex. proxyurl.ngrok.app, sans le https://).
  3. Enregistrez le fichier docker-compose.yml.

05 Flux multi-appareils

Pour tester le flux multi-appareils (Cross Device) sur mobile ou tablette, scannez directement le QR code de la requête VP.

  • Pour les identifiants utilisant client_id_scheme: pre_registered, le portefeuille ne pourra pas partager le VC : votre application Verify locale n'est pas pré-enregistrée auprès du portefeuille.
  • Pour les identifiants utilisant client_id_scheme: did, le portefeuille pourra partager le VC normalement.
  • Pour activer pre_registered, ajoutez votre client_id dans mimoto-trusted-verifiers.json, référencé par Inji Wallet.

06 Flux même appareil

Pour tester le flux même appareil (Same Device) sur mobile ou tablette, ouvrez l'URL de votre proxy, par exemple https://proxyurl.ngrok.app. L'application s'ouvrira directement.

07 Exécution avec Docker Compose

Terminal
cd docker-compose
Ports requis

Assurez-vous que les ports 3001 (interface), 8080 (API) et 5437 (PostgreSQL) sont libres sur votre machine.

Construisez et démarrez tous les services :

Terminal
# si Docker Compose est installé en version autonome
docker-compose up -d

# si Docker Compose est installé comme plugin de la commande docker
docker compose up -d

Cela démarre trois services :

verify-serviceAPI back-end
verify-uiInterface front-end
postgresBase de données
ServiceAdresse
Interface (UI)http://localhost:3001
API — Swaggerhttp://localhost:8080/v1/verify/swagger-ui/index.html

Arrêter l'application

Terminal
docker-compose down   # version autonome
docker compose down   # plugin docker

Réinitialisation complète (supprime aussi les volumes)

Terminal
docker-compose down -v   # version autonome
docker compose down -v   # plugin docker
